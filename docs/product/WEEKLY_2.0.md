# 花语周报 2.0：实现说明（P0 地基 + P1 的四个模块）

状态：**已实现，默认关闭**（`WEEKLY_INSIGHTS_OWNER_IDS`，2026-10-29）。只有离线测试和本地网页假数据检查，
**没有调用过真实模型**，迁移**没有**在任何数据库上跑过，没有部署。产品方向以主人的提案为准：
[WEEKLY_2.0_PROPOSAL.md](WEEKLY_2.0_PROPOSAL.md)（原文不改）。本文件只记录现在的代码做了什么、和提案哪里不同、还差什么。
它替代了第一阶段的说明（原 `WEEKLY_INSIGHTS_V1.md`，见 git 历史）。

一句话：开关名单里的人，周报不再有复述段（“并排放”“本周一句”），改成 **标题 → 主洞察 → 本周花束（心情曲线）→
次洞察 → 那时与现在（“还有一件事”）→ 花语卡 → 给下周的问题**。模型只在两端：抽取（可选 Haiku）和措辞（Sonnet）；
中间的统计、数字、选卡和最后的校验全是代码。任何一步失败，周报只会变短或改用代码模板，不会出错，也不会退回旧版复述。

## 四层流水线

| 层 | 文件 | 做什么 |
|---|---|---|
| 1 抽取 | [lib/insight-extract.js](../../lib/insight-extract.js) | 每条 Event 的记忆存好后，排一个 `INSIGHT_EXTRACTION` 任务（只给开关名单里的人）。抽出人/地点/活动、打算、自问、自我评价、身体信号、小好事；每项存原文和在 `Event.content` 里的 `[start, end)` 位置，存进 `EventInsightExtraction`。 |
| 2 计算 | [lib/insight-compute.js](../../lib/insight-compute.js) | 读本周＋前四周（短周报原有的 source fence），按门槛出候选，写好每条的事实句和数字，排序。 |
| 3 写作 | [lib/insight-write.js](../../lib/insight-write.js) | 一次 Sonnet 调用，输入**只有**候选（E/S 别名、事实句、引文），输出 `headline`、`insights[{id, role, text, evidence_ids, picks}]`、`question`。 |
| 4 校验 | [lib/insight-validate.js](../../lib/insight-validate.js) | 逐条检查，不过就丢；主洞察丢了由下一名补；标题和问题不过就用代码模板。 |

### 1. 抽取

- **默认是代码规则**（词表＋句式，和第一阶段同一套规则，搬进了 `insight-extract.js`）。
  只有同时设了 `AI_INSIGHT_EXTRACTION_PROVIDER=anthropic` 和 `AI_INSIGHT_EXTRACTION_MODEL=claude-haiku-5-5` 才调 Haiku（经 AI Gateway，
  每天每人最多 100 次，计入现有美元上限）。**这是付费推理，开之前要主人单独批准。**
- 模型的输出也要对回原文：找不到原样文字的项直接丢；打算/自问/自我评价一律扩成整句。模型调用失败或被拒，照样存代码规则的结果。
- 敏感内容（`immediateSupportRequired` ＋ 自伤/暴力/性词表，或模型判 `sensitive`）：这条 Event 什么都不存（`status: SENSITIVE`）。
- 存之前在同一事务里重新确认授权、任务认领，并且 Event 没被改过；改过就不存（`SOURCE_CHANGED`）。
- 读的时候（`spanView`）每一项都重新对一遍：文字还在原位置才用，所以改过的 Event 不会引用旧话。没有存储结果的 Event 现算规则。
- 数据去向：Event 删除、账户删除时级联删除；**关闭 Memory 时和记忆、周报一起删除**（`lib/ai-consent.js`）。
- 历史回填：[scripts/backfill-insight-extraction.js](../../scripts/backfill-insight-extraction.js)，只排任务，默认只数不排
  （`INSIGHT_BACKFILL_APPLY=true` 才排），必须写明 owner id，默认回看 90 天。配了 Haiku 时每个任务是一次付费调用，每次实际运行要主人批准。

### 2. 计算（已做的模块）

| 类型 | 门槛（不满足就没有候选） | 事实句（代码写，zh） |
|---|---|---|
| `SAID_BEFORE` 说过的话 | 打算之后还有 ≥3 条 Event，其中 ≥1 条写到同一关键词；打算或提到它的记录至少一条在本周 | 10月7日你写过：“我想每天早上跑步。”之后的 m 条记录里，有 c 条写到“跑步”。 |
| `HIDDEN_LINK` 隐藏关联 | 某人/地点/活动在 ≥3 条有心情的 Event 里，≥1 条在本周，其余 Event ≥2 条；“亮”占比 ≥ ⅔ 且比五周总体高 ≥ 25 个百分点 | 这五周有 n 条记录写到“妈妈”，其中 k 条的心情是开心、平静、治愈或温柔；全部 N 条记录里是 B 条。 |
| `SMALL_GOODS` 好事清单 | 本周亮心情 Event 里 ≥2 句小好事（最多 6 句） | 无（模型挑 2–4 句，代码原样列出） |
| `OPEN_QUESTION` 没回答的问题 | 本周的自问，之后没有 Event 再写到它的关键词；最多 2 个 | 无（原句由代码引用） |
| `TREND` 走向（兜底） | 本周 ≥4 个心情，前半周（一到四）和后半周（五到日）明显变亮或变暗 | 前半周多是「飘忽」，后半周「治愈」多了起来。（只用代码句，不发给模型措辞） |

- 主洞察按提案的优先级挑：说过的话 > 隐藏关联 > 好事清单 > 没回答的问题 > 走向；**上周的主洞察类型这周让位**
  （从上周保存的 `HEADLINE.insightType` 读）。其余按 `新鲜度 × 证据强度 × 情感显著度` 排，最多 6 个候选。
- 本周少于 3 条 Event：不出洞察，标题是“这周的花还在长”，问题是“这周有哪一刻，你想记下来？”，**不调用模型**。
- **时间回声**（[lib/insight-echo.js](../../lib/insight-echo.js)）：这周的一句话，和一年内、至少 30 天前自己写过的几乎一样的一句。
  英文先用已存的 BGE 向量找出相近的旧记录，再由代码挑最接近的一对整句；中文没有向量，直接用代码比较句子（共同的字对、
  最长的共同片段）。两句都要仍是原记录里的整句、都不敏感；旧记录在五周之外时，会按 id 加进周报的来源核对
  （`sourceFence.echoSources`）。回声不发给模型，放在“还有一件事”（取代那时与现在），只有这周只找到它时才当主洞察。
  删除那条旧记录时，引用它的周报也会删除（删除时检查这个人之后所有的周报）。

### 3. 写作

- 仍是**一次** Sonnet 调用（`claude-sonnet-5-5`），合约版本 `weekly-2.0`。包里没有 id、日期、心情和分数，只有别名；
  放不下网关的 8192 字节时从分数最低的候选开始去掉。
- 只剩代码兜底的走向、或者没有候选时，不调用模型（`REPORT_TEMPLATE_ONLY`）。
- 模型侧失败（超时、网络、提供方错误、限流、输出格式错、额度用完）时，这一周用代码模板生成，`provider` 为空；
  授权、配置、任务认领的错误照旧报错，不降级。

### 4. 校验（任何一条不过，只丢那一条）

1. `evidence_ids` 必须非空，而且全是这个候选自己的证据 Event；候选 id 必须是送出去的。
2. 引号里的文字必须是证据 Event 的完整分句（沿用 `groundedSentence`）；候选自己的主题词、关键词和心情名可以带引号。
3. 数字只能来自这个候选的事实句或证据原文。
4. 词表里的人/地点/活动、英文大写词，必须出现在这个候选的证据里。
5. 禁词只看引号**外**：因果（因为、导致、所以、说明你、由于、让你…）、诊断标签（焦虑症、抑郁、创伤、人格、你是一个…的人）、
   预测（预示、注定、将会、未来会、以后会…）、建议（你应该…），以及短周报原有的解读词表。
6. 长度：洞察 zh ≤80 字 / en ≤240 字符；标题 ≤16 字 / 48 字符；问题必须是一句、以问号结尾。
7. 证据 Event 现在必须仍不敏感、仍包含被引用的话。好事清单的 `picks` 必须是 2–4 个不重复的本候选引文 id。

整篇超长时先从后往前去掉次洞察，再去掉“那时与现在”。

## 花语卡

由主洞察类型决定（[lib/petal-card-match.js](../../lib/petal-card-match.js) `INSIGHT_CARDS`），owner + 周 的哈希只在同类型的几张里打破平局，
同一周重做还是同一张；卡面加“为什么是这张”（代码模板，只填代码给的字段）。

| 主洞察 | 卡池 | 为什么是这张（zh） |
|---|---|---|
| 时间回声（未做） | 命运之轮、月亮 | 你在{日期A}和{日期B}写下了相似的话。… |
| 说过的话 | 战车、权杖三 | 你说过“{原句}”，之后 {N} 次写到它。 |
| 隐藏关联 | 圣杯二、恋人 | 写到{主题}的日子，你常选『{心情}』。 |
| 好事清单 | 圣杯三、太阳 | 这周的晴朗来自{小事1}、{小事2}。 |
| 第一次 | 愚者、权杖王牌 | 这是你第一次写到{关键词}。 |
| 没回答的问题 | 隐士、女祭司 | 你问了自己：“{问题原文}” |
| 身体信号 | 宝剑四、节制 | 写到{类别}的 {N} 条记录，你都选了『{心情}』。（不是全部时：…里，k 条你选了『{心情}』。） |
| 走向：变亮 / 变暗 | 星星、审判 / 宝剑四、隐士、力量 | 前半周多是『{A}』，后半周『{B}』多了起来。 |

“说过的话（没再提）”那一行没有做：主人 2026-10-29 决定之后没再写到的打算不出候选。卡池里都没有重牌（测试会查）。

- App（[reflection.tsx](../../mobile/src/app/reflection.tsx)、[ShortWeeklyReport.tsx](../../mobile/src/components/features/ShortWeeklyReport.tsx)、

  2.0 周报（`HEADLINE.reportVersion` 为 `weekly-2.0`）是书里的**一个跨页**，不再有“摘要 / 主题 / 规律”三个标签，
  也没有旧版的主题、规律和“证据不足”说明。
  - **左页：** 日期、一句话标题（花开后浮现）；**本周花束**：每条 Event 一朵花，用它在花园里真正长出的那种花
    （从花园读 `speciesCode`；没种下、已删或读不到时按心情用固定的一种花），按星期排开，不按心情分高低。一天一两朵并排
    站在地平线上；更多时排成每排最多三朵的几排，越早写的越靠后、略高略小，所以一天写多少条都能看到每一朵。点花看那天的原文。
    下面是**这周的心情**：8 种心情的八维图，用手绘花瓣画成，每种心情固定一个方向，花瓣长短是这周选它的次数；每片花瓣
    都标着心情名和次数（颜色只是装饰，不靠颜色区分）。心情名和记录时选的一致（开心、温柔、低落、治愈、愤怒、好奇、迷茫、平静）。
  - **右页：** 主洞察（日期小标签可展开原文）→ 次洞察（左右滑动）→ “还有一件事” → 花语卡 → 给下周的问题（只有问题本身）
    → “举报最终内容” / “Report final output”。
  - **排版：** 同一块里的文字一个字号（正文 14、标题 21、小标签 11）。页面不滚动：写不下的块翻到下一页（“‹ 1 / 2 ›”），
    一个块不会被拆开；只有一个块本身比整页还高时，那一页可以滚动。书还是原来的大小。
  - **书架：** 进亭子时三本书都在书架上，书桌上的书上写着“从书架上取一本书”。点书架上画出来的书：绿书是周报，蓝书是月报，

    页面里也没有那一排小书脊。系统开了“减少动态效果”时直接打开。
  - **说明放在书架第三本书“关于”里：** 安全提示、“花语卡只是陪你回看自己……”、回看怎么写成的、怎么隐藏和举报；周报和
    月报里都不再出现这些说明。
  - **打开时：** 直接显示内容（2026-10-29 起不再有花苞和花瓣的开场动画）。以下为旧说明：整个跨页先只有“你这周的花开了”和一朵手绘番红花苞。轻点后花苞展开：这周每条记录一片花瓣，颜色是那条
    记录选的心情（同一片手绘花瓣按 8 种心情上色，`assets/reflection/weekly/petals/`），然后花苞淡出，
    花一朵朵升起（每朵 360ms、错开 110ms、上移 8px），然后日期和标题浮现，右页最后淡入。左右两页共用一次开花；
    同一份周报在这次使用 App 期间只开一次；系统开了“减少动态效果”时没有花苞，直接显示。
  - **没洞察的周：** 只显示日期、“这周的花还在长”和一个轻问题（带“写一条来回答”），右页只留插画。后端对 2.0 用户
    先走 2.0，再查证据：只有 0–1 条记录的周也存这份代码周报，不再存空的“证据不足”周报。
  - **手机：** 竖着拿时左页在上、右页在下，同一页里滚动；横着拿时左栏是左页、右栏是右页。

  - **隐藏：** 每条洞察右下角只有一个“隐藏”。点了以后这一条收成一行“已隐藏。”，可以“重新显示”。（后端仍接受

    `POST /ai/reports/weekly/:id/insights/:index/feedback`，只能改自己的周报，需要 Memory 授权），

## M5：花语年鉴（2026-10-29）

代码在 [lib/almanac.js](../../lib/almanac.js)。**打开时用代码现算，不保存、不调用模型**：所以不花钱，删掉一条记录后年鉴自然就没有它了，
也不需要新表或迁移（原来的 `YearlyReport` 表没有正文字段，没动它）。接口 `GET /ai/almanac`（能打开的年份）和 `GET /ai/almanac/:year`，
只认登录的人自己，需要 Memory 授权。**今年的年鉴从 12 月 25 日（账户时区）起能打开**，往年随时能打开（提案写“12 月最后一周”，这里取 25 日）。
入口在书架奶白书“花语集”最上面的“2025 花语年鉴”。

| 板块 | 内容 | 规则 |
|---|---|---|
| 标题和一句话 | “你的 2026 花语年鉴”“这一年你在 N 天里写下了 M 条记录。” | — |
| 十二个月的花园 | 12 个小日历，每天一片手绘花瓣（当天选得最多的心情，并列取后选的），没记录的日子是一个浅土点 | 只用允许 AI 处理的记录 |
| 回声最多的主题 | 写得最多的人/地点/活动：“‘室友’在 3 个月里出现了 3 次。”＋第一次和最近一次写到它的原话 | ≥3 条且跨 ≥2 个月 |
| 第一次时间线 | 这一年周报里出现过的“第一次”：日期＋词（不引原文） | 隐藏/标不准确的不算；那条记录删了就不显示；最多 24 个 |
| 年度好事前 10 | 亮心情记录里的小好事，同样的话写得越多越靠前 | — |
| 年度花语卡 | 这一年周报里抽到最多的卡（并列取最近的），下面叠着每次的“为什么是这张” | — |

- 屏蔽词对主题、第一次、好事、卡的理由都生效。
- **分享海报没做**：和周报分享卡一样，要先装 `react-native-view-shot` + `expo-sharing` 并重新打原生包；做的时候按提案只放用户勾选的内容，默认不含原文。

## M4：月报 2.0（2026-10-29）

代码在 [lib/monthly-insights.js](../../lib/monthly-insights.js)。**全部由代码写，不调用任何模型**（不花钱）；开关
`MONTHLY_INSIGHTS_OWNER_IDS`（逗号分隔 id 或 `*`，默认关、格式错也算关）。名单外的人仍是原来的月报（Opus / Workers AI）。
名单内的人：worker 不预留费用、不找模型，直接用代码写好保存（`provider` 为空）。读的数据：本月和上个月的记录（月报原有的来源核对范围，没扩大）、
本月的周报（按周一落在本月）、抽取结果、屏蔽词。

| 板块 | 内容 | 门槛 / 规则 |
|---|---|---|

## M3：周报的其余模块（2026-10-29）

都在 [lib/insight-compute.js](../../lib/insight-compute.js)，门槛达不到就不出；主洞察优先级仍是
时间回声 > 说过的话 > 隐藏关联 > 好事清单 > 第一次 > 没回答的问题 > 反复的句式 > 身体信号 > 节律 > 走向。

| 类型 | 门槛 | 事实句（zh） | 说明 |
|---|---|---|---|
| `FIRST_TIME` 第一次 | 第一条（允许 AI 处理的）记录在本周开始前 ≥28 天；本周记录里的人/地点/活动词，之前所有允许 AI 处理的 Event 都没写过（读报告输入时逐词查库，只要“有/没有”，最多 12 个词，不保存） | 这是你第一次写到“面试”。 | 每周最多一个，取本周最早的；可以当主洞察，卡池 愚者 / 权杖王牌 |
| `BODY_SIGNAL` 身体信号 | 同一类（睡眠、累、身体不舒服、运动）在五周里 ≥3 条，≥1 条在本周；其中一种心情 ≥3 条且占 ≥⅔ | 这五周有 3 条记录写到睡眠，你都选了『迷茫』。/ 其中 k 条你选了『…』。 | 用类别名，不加引号，不假装是用户的原话；卡池 宝剑四 / 节制 |
| `RHYTHM` 节律 | 本周＋前三周 ≥12 条；某种心情 ≥4 条（≥1 条在本周），≥⅔ 写在一天里的同一时段，而这个时段在全部记录里占 ≤½ | 这四周你选『迷茫』的 4 条记录里，有 4 条写在晚上 22 点以后。 | 时段按账户时区的当地钟点：早上 5–11、下午 11–17、傍晚到晚上 17–22、22 点以后；没有引文；没有专属卡池（按心情选卡） |
| `SELF_TALK` 反复的句式 | 本周同一个自我评价开头（我是不是太 / 我总是 / I'm so…）≥3 次 | 这周你写了 3 次“我是不是太……”。 | **安全规则**：走向变低的周不出；只数次数，原句不引用、也不发给模型；永远不当主洞察（只有它时整条不出）；同样的自问句也不再当“没回答的问题”引用 |

  第一条记录不满 4 周时“从第一条记录算起满 4 周，就能看到『第一次』”。

## 什么时候写、谁来写

- 周报从**周日晚 23:59（用户时区）**起就可以写，不用等到周一；周的边界不变，周报只读到它写出那一刻为止的记录
  （见 [time.md](../../time.md) §3）。App 打开书时按同一规则写这一周。
- **服务器自动写**（`AI_WEEKLY_AUTO_SCHEDULE_OWNER_IDS`，默认关闭）：生产环境每 20 分钟的定时任务给名单里、开着 AI 记忆的
  每个人排一次这周的周报（每周只排一次，和手动触发用同一个任务键）。记录少的周是代码写的，不花钱；其余每人每周一次
  模型调用。打开这个名单要主人批准。提醒（推送）以后再做。

## 开关、版本和时间

- `WEEKLY_INSIGHTS_OWNER_IDS`：逗号分隔 id 或 `*`；未设、空、格式错 → 没人开。只对已在 `AI_WEEKLY_SHORT_OWNER_IDS` 里的人起作用。
  抽取任务也只给名单里的人排。
- `REPORT_NARRATIVE_GENERATION_VERSION` 不变：已经生成过的周不会重做。
- 不新增时间边界、不读时钟，见 [time.md](../../time.md)“Weekly 2.0”一节。
