## 一页结论

删掉现在的 AI 复述段。周报 2.0 不再总结用户写了什么，只把用户自己写过、选过、说过的事连起来，让他看到自己看不到的规律。

为什么要删： 复述只是把用户已经知道的事再说一遍，信息量为零，还有改写失真的风险。用户读完不会觉得被看见，只会觉得被敷衍。

新系统做什么： AI 只负责从日记里抽取事实（人、事、意图、问题），统计和关联全部由代码完成。最后 AI 只组织语言，每一句都必须挂上原文证据。

三个承诺：

| 承诺 | 用户感受到的 | 怎么保证 |
|---|---|---|
| 不编造 | 每句话都能点开看到自己的原话 | 引用逐字校验，数字只由代码算，不过校验就不显示 |
| 有深度 | "原来我是这样的"，是新发现，不是复述 | 洞察来自跨时间的连接：共现、回声、说过的话、变化 |
| 持续玩 | 每周期待开报，愿意多写一点 | 开报仪式、洞察收藏、跨周线索、花园生长，全部不靠惩罚 |

北极星指标： 周报证据点开率（衡量信任）和次周记录留存（衡量持续玩）。

## 设计原则

六条原则决定每个功能能不能做，冲突时按顺序取舍。

1. 有据才说。 没有原文证据或代码计算结果的话，一个字都不说。
2. 照见，不评判。 只描述共现、重复和变化，不解释原因，不诊断，不给建议；结尾只提问题。
3. 说新的。 用户已经知道的事（"你这周记了 5 条"）放到角落，首屏只放他没意识到的。
4. 宁缺毋滥。 达不到样本门槛就不显示。一周只有一条好洞察，比五条凑数的强。
5. 靠好奇留人，不靠焦虑留人。 没有断签惩罚，没有"你已经 3 天没记录"的推送，每周只推一次周报。
6. 用户掌控。 可以把某个人名或主题设为不参与洞察，每条洞察都能标"不准确"或隐藏。

## 首屏体验：开报是一个仪式

每份周报保证至少一个"被看见"的时刻，而且放在用户滑完之前就能遇到的位置。

开报仪式： 每周固定时间（默认周日晚 8 点，可改）推送一句"你这周的花开了"。打开先看到一朵花苞，轻点展开；每片花瓣是本周一条 Event，颜色对应用户选的心情。花开完，一句话标题浮现。

页面顺序：

1. 一句话标题：本周最显著的那条洞察，16 个字以内，只陈述事实。
2. 本周花束：替代现在的心情曲线，每条 Event 一朵花，按天排开，点花看当天原文。
3. 主洞察卡：一张大卡，下方是可展开的原文证据。
4. 次洞察：2 到 3 张小卡，左右滑动。
5. "还有一件事"：如果本周有时间回声，放在这里作为最后揭晓的彩蛋。
6. 花语卡：由主洞察决定（见花语卡 2.0）。
7. 给下周的一个问题：可以直接点"写一条来回答"，以及收藏、分享。

惊艳时刻的优先级： 时间回声 > 说过的话 > 隐藏关联 > 好事清单 > 第一次 > 其他。排序靠前的达标就当主洞察。

一句话标题示例：

| 主洞察类型 | 标题示例 |
|---|---|
| 时间回声 | 这句话，你在三月也写过。 |
| 说过的话 | 周二的那个打算，你做到了 3 天。 |
| 隐藏关联 | 有小林在的日子，你常是温柔的。 |
| 走向变化 | 周五之后，你的花开始变亮。 |
| 好事清单 | 这周让你晴朗的，是很小的事。 |

记录太少的一周（少于 3 条）： 不出洞察，显示"这周的花还在长"，配一条过去收藏的洞察或一个回声，再加一个轻问题引导记录。

## 洞察模块库

共 11 个模块，周报从中按得分挑 1 个主洞察和 2 到 3 个次洞察；每个模块都有样本门槛，达不到就不出。

| 模块 | 用户看到（示例） | 数据与算法 | 显示门槛 | 为什么惊艳 |
|---|---|---|---|---|
| 时间回声 | "10 月 24 日和 3 月 12 日的你，写了几乎一样的话。"下面并排两段原文 | 每条日记存向量，找本周条目在全部历史里最相似的一条 | 相似度高于阈值，且相隔 30 天以上 | 两段都是原话，零编造，最有"哇"感 |
| 说过的话 | "周二你写『想早点睡』，之后 4 条里有 3 条提到熬夜。" | 抽取意图句（想、要、打算），在之后的条目里查相关提及 | 意图句之后至少还有 3 条记录 | 像一个记得你说过什么的朋友 |
| 隐藏关联 | "提到小林的 5 条里，4 条你选了『温柔』。" | 抽取人、地点、活动，代码计算与心情的共现和提升度 | 同一实体出现 3 次以上，且比例明显高于用户平均 | 用户没意识到的规律，有数字支撑 |
| 好事清单 | "这周让你选『晴朗』的：一杯热可可、和妹妹视频、雨停了。" | 从明亮心情条目里抽取具体的小事，原词列出 | 至少 2 件 | 帮用户留住容易忘的好时刻 |
| 第一次 | "这是你第一次写到『辞职』。" | 新出现的人、地点、关键词，对比全部历史 | 用户累计记录 4 周以上 | 标记人生节点 |
| 没回答的问题 | 原样列出这周问过自己的问题："我到底想要什么？" | 抽取自问句，不作回答 | 至少 1 句 | 安静、有深度、不说教 |
| 反复的句式 | "这周你写了 3 次『我是不是太……』" | 抽取自我评价句式，原文计数 | 3 次以上，且受安全规则限制 | 照见自我叙事 |
| 身体信号 | "提到没睡好的 3 天，都选了『迷茫』。" | 抽取睡眠、疲惫、生病、运动，与心情共现 | 同类信号 3 次以上 | 把情绪落到可以改变的地方 |
| 节律 | "你的『迷茫』大多出现在晚上 10 点后。" | 代码按时段、星期统计心情 | 本周加前 3 周至少 12 条 | 不用读日记也能发现的规律 |
| 走向 | "前半周多是安静，后半周疗愈多了起来。" | 沿用现有的前后半周规则 | 至少 4 条 | 延续现有能力，作为兜底 |
| 线索更新 | "你在跟进的『早睡』这条线：这周提到 2 次。" | 用户主动跟进的洞察，每周自动回查 | 用户开启跟进 | 让周报和周报之间连起来 |

排序得分： 新鲜度 × 证据强度 × 情感显著度。新鲜度看这类洞察最近几周有没有出现过；证据强度看样本数和比例；情感显著度看涉及的条目有没有用户写得较长或标记过的。同一类型连续两周不当主洞察。

## 花语卡 2.0：卡由洞察决定

卡不再按心情计数选，而是由本周主洞察的类型决定，卡面上写明"为什么是这张"。哈希只在同一类型有多张候选时用来打破平局，保证同一周刷新结果不变。

卡面结构： 卡名 → 卡语（提前写好）→ "为什么是这张"（按模板拼接主洞察）→ 卡的提问（即"给下周的一个问题"）→ 免责声明。

映射示例（需对照现有 69 张卡池的标签确认）：

| 主洞察 | 候选卡 | "为什么是这张"模板 |
|---|---|---|
| 时间回声 | 命运之轮、月亮 | 你在 {日期A} 和 {日期B} 写下了相似的话。命运之轮说的是会回来的东西。 |
| 说过的话（有后续） | 战车、权杖三 | 你说过 {意图}，之后 {N} 次写到它。 |
| 说过的话（没再提） | 宝剑二、女祭司 | 你写过 {意图}，之后它安静了。不评判，只是提起。 |
| 隐藏关联（人） | 圣杯二、恋人 | 写到 {人名} 的日子，你常选『{心情}』。 |
| 好事清单 | 圣杯三、太阳 | 这周的晴朗来自 {小事1}、{小事2}。 |
| 第一次 | 愚者、权杖王牌 | 这是你第一次写到 {关键词}。 |
| 没回答的问题 | 隐士、女祭司 | 你问了自己："{问题原文}" |
| 身体信号 | 宝剑四、节制 | 写到 {身体信号} 的 {N} 天，你都选了『{心情}』。 |
| 走向：变好 | 星星、审判 | 前半周多是『{心情A}』，后半周『{心情B}』多了起来。 |
| 走向：变低 | 宝剑四、隐士、力量 | 同上，反向。 |

模板写作规则： 模板只能填入代码给出的字段；卡语和模板人工写、人工审；不使用"预示、注定、将会"之类的预测词。

收藏： 每张抽到的卡进入"花语集"，同一张卡多次出现会叠加每次的"为什么是这张"，变成一张卡的个人历史。

## 月报与年度回顾

月报不是四份周报的汇总，而是讲一个月的变化；年度回顾讲一年的故事，并且是全年唯一一份为分享设计的报告。

月报（每月 1 日）：

| 板块 | 内容 | 来源 |
|---|---|---|
| 本月花园 | 日历视图，每天一朵花，颜色是当天主心情，没记录的日子是空土 | 心情选择 |
| 本月牌阵 | 本月 4 到 5 张周卡排成"开始 → 转折 → 现在"，每张下面一句它所在那周的主洞察 | 周卡与主洞察 |
| 变化对照 | 同一主题前后说法的变化，两段原文并排："8 月写到工作多是『火焰』，10 月多是『平静』" | 抽取的主题与心情共现 |
| 线索追踪 | 本月"说过的话"和"没回答的问题"后来怎样：再提到几次、有没有新的说法 | 意图句、问题句的后续 |
| 本月好事清单 | 全月明亮心情条目里的小事，按出现次数排 | 好事抽取 |
| 本月的人 | 本月常出现的人和与之共现的心情，默认折叠，仅自己可见 | 人名抽取 |
| 给下个月的问题 | 由本月最显著的变化生成 | 主洞察 |

年度回顾"花语年鉴"（每年 12 月最后一周）：

- 12 个月的花园拼成一整年
- 全年回声最多的主题，以及第一次和最近一次写到它的原文
- "第一次"时间线：这一年里新出现的人、地方、念头
- 年度好事清单前 10
- 年度花语卡：全年出现最多的卡，叠加它每次出现的原因
- 分享海报：只包含用户自己勾选的内容，默认不含任何原文

## 持续玩：让周报和下一周连起来

留存的核心是一个闭环：周报提出的东西，要在下一周的记录和下一份周报里得到回应。用户写得越多，洞察越准、越深，他就越想继续写。

下表的每个机制都对应飞轮上的一步，最关键的是从『回应』转回『写下记录』的那半圈：它决定用户下周还会不会来。

| 机制 | 怎么玩 | 带来什么 | 护栏 |
|---|---|---|---|
| 回答问题 | 周报结尾的问题可以直接"写一条来回答"，下周周报会引用这条回答 | 闭环最短的一环，给下周一个记录理由 | 回答可选，不提醒 |
| 跟进线索 | 任意洞察点"跟进"，成为一条线；之后每份周报自动报告这条线的新动静 | 周报之间有连续剧感 | 同时最多 3 条，可随时取消 |
| 花语集 | 收藏洞察和花语卡；同一张卡叠加每次出现的原因 | 收集感，以及一本"关于自己的书" | 不显示"还差 N 张集齐" |
| 解锁深度 | 诚实显示洞察需要的数据量："再记录 2 条，就能看到『隐藏关联』" | 给多写一点一个具体理由 | 只显示真实门槛，不虚设 |
| 给未来的信 | 用户写一句话给几周后的自己，到期出现在那周的周报里 | 情感最强的回访，内容百分之百是用户自己的 | 用户自定日期，可撤回 |
| 花园生长 | 每条记录种一朵花，季节随真实月份变化 | 长期可见的积累 | 没记录的日子是空土，不枯萎、不惩罚 |
| 分享卡 | 一键生成花语卡和一句话标题的图片 | 自然传播 | 默认不含原文和人名 |

通知规则： 每周只推一次周报，每月一次月报，不推送"你已断签"类提醒。

## 防编造与安全规则

所有规则都由代码强制执行，不依赖模型自觉；任何一条不通过，这条洞察直接丢弃，整份周报降级为纯模板版本也可以接受。

| 规则 | 实现 |
|---|---|
| 每句话附证据 | 输出 JSON 里每条洞察必须带 evidence_ids，前端渲染成可点击的小标签，点开跳到原日记 |
| 引用必须是原文 | 代码逐字比对引号内文字是否在对应条目中出现，不符合就丢弃 |
| 数字只能由代码算 | 模型输入里的数字是代码算好的；输出里出现输入中没有的数字就拒绝 |
| 实体必须存在 | 输出里出现的人名、地点、关键词必须在抽取结果里能找到 |
| 不说因果 | 禁用词表：因为、导致、所以、说明你；只允许"……的时候，常常……" |
| 不诊断、不贴标签 | 禁用词表：焦虑症、抑郁、创伤、你是一个……的人、你应该 |
| 不预测 | 禁用词表：预示、注定、将会、未来会 |
| 样本门槛 | 每个模块的门槛见模块库，不达标不显示 |
| 安全优先 | 本周有条目触发"需要支持"提示，整周不出洞察，改为显示求助资源 |
| 敏感内容不引用 | 涉及自伤、暴力、性的条目不进入抽取和引用 |
| 负面自我评价慎用 | "反复的句式"在走向为变低的周不显示；显示时只陈述次数，不放大，后接温和的问题 |
| 隐私 | 用户可屏蔽人名或主题；分享卡默认不含原文和人名 |
| 用户可纠正 | 每条洞察有"不准确"和"隐藏"，反馈进入评估集 |

## 技术架构

四层流水线：模型只出现在两端（抽取和写作），中间的统计和最后的校验全部是代码，所以模型没有编造的空间。

模型输出的任何一句话都要经过校验层才能进入周报，失败只会让周报变短，不会让它出错。

1. 抽取层（每条日记写完后跑一次，结果缓存）

| 字段 | 内容 | 用于 |
|---|---|---|
| entities | 人、地点、活动，带类型 | 隐藏关联、第一次、本月的人 |
| intents | 意图句原文（想、要、打算） | 说过的话、线索 |
| questions | 自问句原文 | 没回答的问题 |
| self_talk | 自我评价句原文 | 反复的句式 |
| body | 睡眠、疲惫、生病、运动 | 身体信号 |
| small_goods | 具体的小事原词 | 好事清单 |
| sensitive | 是否涉及敏感内容 | 安全过滤 |
| embedding | 整条日记的向量 | 时间回声 |

每个抽取项都带 entry_id 和原文起止位置，所以之后的任何引用都能回到原文。抽取用小模型，只跑一次，历史数据可以分批回填。

2. 计算层（纯代码）： 统计共现和提升度、检查门槛、做向量检索、查意图句后续、算排序得分，输出候选洞察列表；每条带类型、数字、证据 id 和可用的原文片段。

3. 写作层（每用户每周一次调用）： 输入只有候选洞察 JSON。模型从中挑主洞察和次洞察，用温和的语气写成短句，输出 JSON：headline、insights[{id, text, evidence_ids}]、question。

4. 校验层（纯代码）： 逐条执行防编造规则，不通过就丢弃该条；主洞察被丢弃时用下一名补上；全部失败就降级为模板句。

## 指标、上线顺序与开放问题

先用最惊艳、最容易验证真伪的三个模块上线，用证据点开率和"不准确"率证明信任，再扩展。

指标：

| 指标 | 衡量什么 |
|---|---|
| 周报打开率 | 开报仪式是否让人期待 |
| 证据点开率 | 用户是否在意、是否想核对，北极星之一 |
| "不准确"标记率 | 抽取和写作的质量，高于阈值就暂停该模块 |
| 收藏率、跟进率 | 洞察是否有长期价值 |
| 问题回答率 | 闭环是否转起来 |
| 次周记录留存 | 是否持续玩，北极星之一 |

上线顺序：

1. P0 地基： 删除复述段；上线抽取层和校验层；历史日记分批回填抽取和向量。
2. P1 惊艳： 时间回声、说过的话、隐藏关联、好事清单，以及新首屏（开报仪式、一句话标题、本周花束）。
3. P2 闭环： 花语卡 2.0、花语集收藏、跟进线索、回答问题。
4. P3 月报： 本月花园、本月牌阵、变化对照、线索追踪。
5. P4 年鉴与其余模块： 花语年鉴、给未来的信、节律、身体信号、反复的句式。

开放问题：

- [ ] 付费分层：抽取对所有人开放，还是时间回声等深度模块只给付费用户？
- [ ] 隐私：向量和抽取结果存在哪里，用户删除日记时是否同步删除？
